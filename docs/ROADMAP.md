# JERCPLD 路线图（严格串行）

> 形态：**LeviLamina 原生 C++ mod**，装进真实 BDS 1.26.51 进程内，在包收发路径做跨版本翻译。
> 唯一交付目标：26.30–26.62 任意版本客户端能连上 26.50/26.51 的 BDS 并真正进入世界（稳在服务端、能移动、地形不花、物品栏不错乱）。

## 执行规则

1. 一次只有一项处于 `in_progress`，完成并通过验收才允许开始下一项。
2. 每项必须有可执行的验收标准与判定方法；不能靠「看起来对了」。
3. 同一失败方案最多尝试两次，第三次必须换路，并把决策点写入 `docs/BLOCKERS.md`。
4. 每轮结束更新 `docs/STATE.json`（当前项、状态、最后更新时间、阻塞原因）。
5. 禁止并行铺功能、禁止顺手扩展。

## 串行清单

### S1 最小自检客户端（已完成）

- 交付：`tools/verify-client/`，基于 PrismarineJS `bedrock-protocol 3.61.0`（MIT）。
- 范围：**只做握手 + StartGame 判定**，不做区块、物品、玩法验证。
- 实测：2026-11-08，RakNet 路径，1.9 秒收到 StartGame，1295 个方块属性，PASS。
- 边界：**该结论仅覆盖 RakNet 路径**；正式环境是 NetherNet，必须由真实客户端复核（见验证清单）。

### S2 可交付形态（当前进行中）

- 交付：`mod/JERCPLD.Mod` 构建出 `JERCPLD.dll`；一键安装脚本；BDS 启动横幅。
- 内容：原生 mod 入口、ASCII 艺术横幅（mod 名称、自身版本、适配服务端版本与协议号、可接受客户端范围、翻译开关状态）、配置文件读取（目标版本、开关，无 UI）。
- 验收：真实 BDS 1.26.51 重启后日志出现完整横幅与已加载行，进程稳定。
- 判定：BDS 日志匹配横幅标记与 `loaded`；控制台无异常退出。

### S3 bedrock-protocol C++ codec 固定版本并构建

- 交付：固定 tag/release 的 `EndstoneMC/bedrock-protocol` 源码快照 + 构建产物，记录 SHA256。
- 内容：`find_package(bedrock-protocol CONFIG REQUIRED)`；MSVC `/std:c++latest /Zc:preprocessor /permissive-`；一次生成含 2193/2225 两套结构体。
- 验收：mod 工程能链接 codec；对所有依赖包 ID 通过 `static_assert(bp::has_packet_v<V, id>)`；按版本对拆编译单元不爆内存。
- 判定：编译日志 0 error；断言覆盖清单写入 `docs/STATE.json` 备注。

### S4 包处理与协议号改写

- 交付：在 BDS 包收发路径挂接 Login / RequestNetworkSettings / NetworkSettings / StartGame 的处理。
- 内容：每连接一个翻译器实例（禁止全局共享）；直线映射（版本 ↔ 统一表示 ↔ 版本）；改协议号并被服务端接受。
- 验收：2225 客户端经 mod 与 2193 服务端完成登录并收到 StartGame。
- 判定：最小自检客户端以 `--version 1.26.60` 输出 PASS；BDS 日志无协议错误。

### S5 翻译正确性（NetherNet 取消后腾出的时间全部投到这里）

- S5.1 多版本进入稳定性：26.30 / 26.40 / 26.45 / 26.60 / 26.62 分别经 mod 进入 2193 服务端，记录失败点。
- S5.2 地形/方块：目标版本下的方块状态哈希与调色板降级正确，地形不花。
- S5.3 物品：物品栈 runtime id / 元数据在目标版本下正确，物品栏不错乱。
- S5.4 实体：元数据槽位在目标版本下正确降级。
- S5.5 每个版本对独立差异表：2193↔2225、2193↔2169、2193↔2168、2193↔1001，禁止 A→B→C 递进链；缺失步骤必须显式报错，不静默降级。
- 验收：每条版本对都有独立差异表与可复现的验证记录。

### S6 诊断能力

- 交付：会话包序列导出（时间、方向、包 ID、包名、输入输出字节、状态、失败原因）。
- 验收：出问题时能定位到具体包；导出文件可由用户直接提供。

### S7 热路径压测

- 交付：合成包压测工具与报告（每包平均耗时、与直通转发对比倍数、分配次数）。
- 验收：报告写入 `docs/PERF.md`，数字可复现。

## 取消项（保留记录，不静默删除）

### C1 NetherNet 自实现 —— 因形态变更取消

- 原要求：UDP 7551 局域网发现、TCP `/v1/join` 与 `/v1/join/{networkId}`、SDP、ICE、DTLS 1.2、SCTP 双通道、P-384 身份断言、分片重组全部自实现。
- 取消原因：产品形态已从独立代理改为 LeviLamina 进程内插件，传输层完全由 BDS 负责；插件只处理包层，接触 NetherNet 既无必要也不应该。
- 处置：该主线整体取消，已投入时间转入 S5 翻译正确性。旧独立代理的 ArkMirage（GPL-3.0）仅作内部参考，不进入分发。

## 验证边界（重要）

| 结论 | 来源 | 是否可放行 |
| --- | --- | --- |
| 握手 / 登录 / StartGame 可通 | RakNet 路径最小自检 | 仅证明协议改写链路可跑，不等于 NetherNet 可用 |
| 协议号改写被服务端接受 | 待 S4 用 RakNet 自检 | 需真实客户端在 NetherNet 下复核 |
| 进世界 / 地形 / 物品 / 实体 | 待 S5 | 必须真实客户端验收 |
